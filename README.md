## Протокол

- Транспорт: TCP, `127.0.0.1`, порт **5000**.
- Клиент отправляет строку `ping\n`, сервер отвечает строкой `pong\n`.
- На любой другой запрос сервер не отвечает, а фиксирует ошибку и закрывает соединение.

## Диаграммы состояний

Алгоритм обеих программ реализован как конечный автомат (`enum class State` и цикл с `switch`) по диаграмме с семинара.

### Клиент

| Состояние | Действие | Успех | Ошибка |
|---|---|---|---|
| `Compose` | `send` строки `ping\n` | `WaitingForReply` | `HandleError` (фатальная) |
| `WaitingForReply` | `recv` с таймаутом 3 с | `ReadingReply` | `HandleError`: таймаут (нефатальная), соединение закрыто или ошибка `recv` (фатальные) |
| `ReadingReply` | сравнение ответа с `pong\n` | `Done` | `HandleError` (нефатальная) |
| `HandleError` | вывод причины | фатальная ошибка или исчерпаны 3 попытки: `Done`, иначе повтор через `Compose` | |
| `Done` | выход, код 0 или 1 | | |

### Сервер

| Состояние | Действие | Успех | Ошибка |
|---|---|---|---|
| `WaitingRequest` | `recv` с таймаутом 5 с | `HandleRequest` | `Error` (таймаут, клиент закрыл соединение, ошибка `recv`) |
| `HandleRequest` | проверка, что запрос равен `ping\n` | `SendingReply` | `Error` (неизвестный запрос) |
| `SendingReply` | `send` строки `pong\n` | `Done` | `Error` |
| `Error` | вывод причины | `Done` | |
| `Done` | закрытие соединения с клиентом, возврат к `accept` | | |

Стрелка «ошибка: ожидание запроса» с диаграммы реализована внешним циклом: после обработки любого клиента (успешной или нет) сервер закрывает его сокет и снова вызывает `accept`.

## Обработка ошибок

Ошибки клиента делятся на **нефатальные** (повторяем запрос, максимум 3 отправки) и **фатальные** (соединение сломано, повтор бессмыслен).

| Ситуация | Что делает программа |
|---|---|
| Сервер не запущен | клиент: `connect: Connection refused`, код выхода 1 |
| Сервер молчит | клиент: таймаут 3 с, повторяет запрос, после 3 попыток завершается с кодом 1 |
| Сервер ответил не `pong` | клиент: `unexpected reply`, повторяет запрос (до 3 попыток) |
| Сервер закрыл соединение | клиент: фатальная ошибка, без повторов, код 1 |
| Клиент прислал неизвестный запрос | сервер: `client error: unexpected message`, закрывает соединение, ждёт следующего |
| Клиент оборвал связь | сервер: `client error: client closed connection`, ждёт следующего |
| Клиент подключился и молчит | сервер: через 5 с `client error: timeout`, закрывает соединение, ждёт следующего |
| Ошибка любого системного вызова | проверяется результат каждого вызова (`socket`, `bind`, `listen`, `accept`, `connect`, `send`, `recv`, `setsockopt`), причина выводится через `strerror(errno)` |

Дополнительно:
- `MSG_NOSIGNAL` в `send`: запись в закрытое соединение возвращает ошибку, а не убивает процесс сигналом `SIGPIPE`.
- `SO_REUSEADDR` на сервере: можно перезапускать сервер без ожидания освобождения порта.
- Таймауты (`SO_RCVTIMEO`) защищают от бесконечного ожидания.
